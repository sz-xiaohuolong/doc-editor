## Problem

用户需要一款类似“wolai”（我来）的模块化块级（Block-based）文档编辑器，追求简洁、沉浸、结构清晰的笔记与知识组织体验，但不希望将笔记数据托管在云端，期望第一版所有文档与数据全部保存在本地，兼具隐私性与掌控感。

## Target User

- 喜欢类 Notion / wolai 块级积木排版、双链引用的知识管理者与个人笔记用户。
- 强烈重视数据主权、隐私安全、追求离线可用，不希望绑定云服务的开发者或写作者。

## Core Scenario

1. 用户在应用中打开或指定一个本地知识库工作区目录。
2. 左侧树状目录：快速创建页面、重命名、拖拽/多层级嵌套、删除。
3. 主编辑区：每个段落/组件为一个独立的 Block，支持回车换行、退格合并、拖拽排序、快捷斜杠 `/` 唤出块类型菜单（文本、各级标题、待办清单、代码块、引用、分栏等）。
4. 本地持久化：编辑过程自动保存至本地磁盘，关闭或重启后数据无损恢复。

## In Scope (拟议范围)

- 核心 Block 积木编辑（基础块类型、快捷斜杠菜单、行内格式加粗/高亮/行内代码等）。
- 多页面管理（左侧树状页面导航、页面增删改查、层级嵌套）。
- 本地文件持久化（工作区目录读写、自动保存、离线直接可用）。

## Out of Scope (第一版明确排除)

- 云端多端同步与账户登录系统。
- 多人实时协作编辑。
- 复杂的数据库/多维表格视图（Database Views）。
- 云端分享链接与导出在线网页。

## Constraints

- 存储必须纯本地，不依赖任何第三方云端 API。
- 启动必须轻量迅速，编辑输入必须流畅无延迟（60fps）。

## Open Questions (需要用户决策)

1. **运行形态与载体**：是做桌面端原生体验应用（如 Tauri/Electron），还是纯现代 Web 应用（基于浏览器 File System Access API 读写本地文件夹），亦或本地轻量 Web 服务？
2. **底层存储文件组织**：是采用“纯 Markdown 文件夹体系”（对外部工具最友好，但需在 frontmatter 记录 block 属性），还是“专有 JSON 树/SQLite 数据库”（对 Block 嵌套和富属性最原生自然）？
3. **wolai 特色能力优先级**：第一版是否必须包含双向链接（`[[页面名]]`）、页面图标/头图（Icon/Cover），还是先聚焦最纯粹的块级图文排版？
